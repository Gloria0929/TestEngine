## 1 引言

### 1.1 编写目的

本文档用于完整描述**测试平台管理系统（TestEngine）**前端的业务与功能需求，作为前端开发、组件设计、Mock 数据搭建、测试验收与协作评审的统一依据。

本文档对照 MeterSphere v3 本地部署环境（组织 ID `100001`）的实际模块结构编写，并结合参考产品《软件需求规格说明书》提炼出「前端可落地」的功能清单。**本文只覆盖前端范围**：页面、路由、组件、交互、状态管理与 Mock 数据方案，不涉及后端接口实现、存储与执行引擎设计。

**读者对象**：前端工程师、UI/交互设计师、测试工程师、产品经理、项目经理。

### 1.2 项目背景

传统测试工作中，用例管理、接口调试、场景自动化、计划执行与缺陷跟踪分散在 Excel、Postman、JMeter、缺陷系统等多套工具中，导致资产难复用、结果难汇总、协作成本高。参照 MeterSphere 将「测试管理与接口自动化」收敛到同一平台的做法，本项目构建一个前端优先的测试平台管理系统，覆盖工作台、项目管理、测试用例、测试计划、接口测试、缺陷管理、系统设置七大一级模块。

本期为**前端先行**阶段：用 Vue 3 完整还原核心交互与页面，数据通过内置 Mock 提供，接口层做统一抽象，以便后续后端就绪后无缝切换。

## 2 总体描述

### 2.1 产品定位

平台定位为团队级持续测试中枢的**前端实现**：在单一应用中沉淀测试资产、完成接口调试与自动化编排、执行测试计划、闭环缺陷，并以「系统 - 组织 - 项目」三级层级组织协作。本阶段聚焦「看得见、点得动、数据真」——页面结构完整、交互闭环、Mock 数据仿真，为后续接入真实后端预留接口。

### 2.2 建设目标

- **资产统一**：功能用例、接口资产、场景脚本与缺陷数据在统一界面管理，减少工具割裂。
- **接口提效**：接口调试、定义、Mock、场景编排、报告在同一项目内闭环。
- **计划可视**：测试计划汇总手工与自动化结果，输出可分享报告。
- **协作可控**：按角色授权、项目数据隔离、操作可审计（前端体现为菜单/按钮级权限）。
- **前后端解耦**：通过统一 API 层 + 可切换 Mock，后端就绪即可低成本对接。

### 2.3 范围

#### 2.3.1 范围内

本期需求覆盖本地 MeterSphere 环境已提供的全部一级能力的前端实现：

工作台、项目管理、测试用例（含评审）、测试计划（含报告）、接口测试（调试 / 定义 / 场景 / 报告 / Mock）、缺陷管理、系统与组织设置、个人中心、全局通知与主题、权限模型。

#### 2.3.2 范围外

- 性能测试（分布式压测、监控大盘）：本地环境未出现，本期不做。
- UI 自动化测试：本地环境未出现，本期不做。
- 后端接口、执行引擎（Task Runner）、数据库、消息队列等非前端实现。
- 被测业务系统本身的功能开发。

### 2.4 用户角色

| 角色 | 层级 | 前端主要可见范围 |
| --- | --- | --- |
| 系统管理员 | 系统 | 系统设置全部入口：用户、用户组、组织、项目、插件、系统参数、模型配置。 |
| 系统成员 | 系统 | 被分配到组织/项目后开展测试工作。 |
| 组织管理员 | 组织 | 组织成员、项目创建、服务集成（Jira/禅道/TAPD 等）。 |
| 组织成员 | 组织 | 进入授权项目开展测试。 |
| 项目管理员 | 项目 | 项目设置、成员/用户组、环境、模板、消息、文件、日志。 |
| 项目成员 / 测试工程师 | 项目 | 编写用例、调试接口、编排场景、执行计划、提缺陷。 |
| 开发工程师 | 项目 | 接口调试、查看 Mock、关注失败报告、修复缺陷。 |
| 测试负责人 | 项目 | 评审用例、制定计划、跟踪进度、发布报告。 |

> 前端通过「当前用户角色 + 权限点」控制菜单显隐与按钮禁用，权限点由系统/组织/项目用户组下发（见 §5.7 与 §4.5）。

### 2.5 运行假设与约束

- **运行环境**：现代桌面浏览器最近两个大版本（Chromium / Firefox / Edge）。
- **构建**：Vite 构建 SPA；`dev` 与 `preview` 均可使用内置 Mock。
- **约束**：前端不持有真实密钥/敏感数据，密码等敏感字段不明文回显；所有数据读写经统一 API 层。
- **Mock 假设**：Mock 数据应覆盖空态、单条、批量、异常（超时/失败）等多种形态，便于前端开发与验收。

## 3 技术架构（前端）

### 3.1 技术选型

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3.5+ | Composition API + `<script setup>`。 |
| 语言 | TypeScript 5.x | 全量 TS，类型约束接口模型与 Mock。 |
| 构建 | Vite 6.x | 开发服务器、HMR、生产构建。 |
| UI 组件库 | Element Plus 2.x | 统一后台组件体系，暗色/亮色主题。 |
| 路由 | Vue Router 4.x | 分层路由 + 权限守卫。 |
| 状态管理 | Pinia | 用户/权限、主题、通知、模块级数据。 |
| 图表 | ECharts 5.x | 工作台概览、报告统计、趋势图。 |
| HTTP | Axios 1.x | 统一封装请求/响应拦截器。 |
| 数据 Mock | Mock Service Worker (MSW) 2.x | 网络层拦截，最接近真实环境；可切换。 |
| 代码风格 | ESLint + Prettier | 统一规范。 |

> Mock 备选方案：`vite-plugin-mock`（轻量）或 `axios-mock-adapter`（纯前端）。默认推荐 **MSW**：在 Service Worker 层拦截请求，前端代码与真实请求无差异，且可将 mock 断言用于测试。

### 3.2 分层架构

```
┌─────────────────────────────────────────────┐
│  视图层 View（页面 / 布局 / 业务组件）        │
├─────────────────────────────────────────────┤
│  组合层 Composables（useXxx 复用逻辑）        │
├─────────────────────────────────────────────┤
│  状态层 Pinia Stores（user/permission/...）  │
├─────────────────────────────────────────────┤
│  服务层 services（按模块封装 API 调用）       │
├─────────────────────────────────────────────┤
│  传输层 request（axios 实例 + 拦截器）        │
│        ↓  ← 可切换：真实后端  ⇄  MSW Mock     │
└─────────────────────────────────────────────┘
```

约定：**视图组件不直接调用 axios**，一律经由 `services` 层；`services` 层只关心「要什么数据」，不关心数据来自后端还是 Mock。

### 3.3 目录结构（建议）

```
src/
├── api/                  # 服务层：按模块划分的 API 封装
│   ├── auth.ts
│   ├── workstation.ts
│   ├── project.ts
│   ├── testCase.ts
│   ├── testPlan.ts
│   ├── apiTest.ts
│   ├── bug.ts
│   └── setting.ts
├── mocks/                # MSW handlers + 种子数据
│   ├── browser.ts
│   ├── handlers/
│   └── seed/             # 组织/项目/用户/用例/接口/场景/缺陷 mock 数据
├── router/
│   ├── index.ts
│   └── routes.ts
├── stores/
├── views/                # 页面级组件（按模块分目录）
├── components/           # 通用业务组件
├── composables/

├── utils/
└── styles/               # 主题变量、全局样式
```

### 3.4 路由设计

一级菜单即路由顶层；二级入口映射子路由。详见附录 A 完整「页面 - 路由 - 组件清单」。路由需支持：懒加载、`meta` 标注标题/图标/权限点/是否缓存，以及全局前置守卫做登录与权限校验。

### 3.5 状态管理（Pinia）

| Store | 职责 |
| --- | --- |
| `useUserStore` | 当前用户信息、角色、登录态。 |
| `usePermissionStore` | 菜单权限点、按钮权限点、可访问路由。 |
| `useAppStore` | 主题（亮/暗）、语言（中/英）、侧边栏折叠。 |
| `useNotificationStore` | 站内通知未读数与列表缓存。 |
| 模块级 Store | 工作台筛选条件、用例树/脑图选中态、场景步骤编辑态等局部共享状态。 |

### 3.6 API 层与 Mock 数据方案

- **API 层**：按模块封装（`api/*.ts`），统一返回类型 `ApiResult<T>`；错误经响应拦截器统一 toast，业务码统一映射。
- **Mock 层**：`mocks/handlers/` 按模块维护 MSW handler；`mocks/seed/` 维护可复用的仿真种子数据（用函数生成，避免污染全局）。
- **切换机制**：环境变量 `VITE_USE_MOCK=true` 时注册 MSW；置 `false` 且配置 `VITE_API_BASE_URL` 时走真实后端。
- **数据仿真要求**：
  - 分页、筛选、排序、搜索在 handler 内真实生效；
  - 写操作（增删改）在内存态内闭环，刷新后重置为种子数据（或本地 `localStorage` 持久化，按需）；
  - 关键链路覆盖**空态**（0 条）与**异常态**（接口超时/失败）以便前端处理。

## 5 功能需求

## 6 核心业务流程

### 6.1 功能测试闭环

创建模块与用例（列表或脑图） → 可选评审 → 纳入测试计划并分配执行人 → 执行并记录结果 → 失败转缺陷 → 生成计划报告 → 缺陷修复后回归。

### 6.2 接口自动化闭环

配置环境 → 调试或导入定义 → 保存接口用例 / 配置 Mock → 编排场景（引用接口、提取变量、断言、控制器） → 服务端或定时执行 → 查看报告 → 失败分析或转缺陷 → 可选加入测试计划统一出报告。

### 6.3 场景引用协作

公共登录场景由专人维护并被业务场景引用。源场景更新后，完全引用自动跟随；若需冻结逻辑则使用复制。参数冲突按「临时 > 场景 > 环境」处理。

### 6.4 登录与授权流程

登录 → 拉取当前用户与权限点 → 构建可访问菜单 → 进入工作台 → 后续所有页面读写经 API 层（Mock/后端）→ 无权限操作被拦截并提示。

## 7 非功能需求

### 7.1 性能

- 列表默认分页，万级数据下筛选响应可接受（Mock 下建议 < 300ms）。
- 场景编辑支持典型业务流（建议不少于 50 步可编辑可执行），步骤树渲染流畅。
- 工作台图表数据按需懒加载，避免首页阻塞。

### 7.2 可用性与体验

- 关键操作有确认；删除进回收站。
- 空态展示友好（如场景 0 条时仍可新建/导入）。
- 支持亮/暗色与中英文。
- 交互闭环：所有按钮/链接均可达、可回退、有反馈。

### 7.3 安全（前端范围）

- 项目数据隔离：越权访问返回统一无权限页，不泄露存在性。
- 敏感字段（密码、凭证）不明文回显。
- 分享链接具备有效期（前端展示失效态）。
- 登录态与权限点不落盘于明文；XSS 防护遵循 Vue/Element 默认转义。

### 7.4 可靠性

- 执行失败给出步骤级错误，而非仅全局失败（报告页体现）。
- 报告清理后历史记录仍在，详情提示「执行结果被清理」。
- while 循环必须可配置超时，防止死循环占满执行机。

### 7.5 兼容性与可维护性

- 支持主流桌面浏览器最近两个大版本。
- 全量 TypeScript，类型与接口模型对齐，保证 Mock → 真实后端切换时改动最小。
- 组件与 composables 高内聚、可复用，命名与目录遵循 §3.3 约定。

## 附录 B Mock 数据清单

| 数据对象 | 建议规模 | 说明 |
| --- | --- | --- |
| 组织 / 项目 | 1 组织 / 3~5 项目 | 组织 `100001` + 示例项目，覆盖空项目与有数据项目。 |
